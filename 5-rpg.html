✅ ETAPA 1 — REQUISITOS FUNCIONAIS Pilares do RPG

📊 RF01 - Estado do Jogo

O aplicativo deve rastrear constantemente os Status do jogador: Vida (10), Energia (8), Chave (Sim/Não) e a Fase atual.

📜 RF02 - Narrativa Dinâmica

Um Label central deve exibir a história, mudando o texto de acordo com a Fase (Stage) atual.

🔘 RF03 - Botões Mutáveis

As ações disponíveis (botões) devem ser destruídas e recriadas a cada tela, refletindo as escolhas da fase.

⚖️ RF04 - Consequências

Se Vida ou Energia chegar a 0, Game Over. Se tiver a Chave na porta final, Vitória. Um botão "Reiniciar" deve limpar o estado.

⚡ ETAPA 6 — CRIANDO O EVENTO DINÂMICO Como os botões virtuais ganham vida?

Como os botões de ação são gerados pelo Python, não podemos clicar neles na aba Design para gerar um evento.

Na Etapa 7, você verá o comando: novo_botao.set_event_handler('click', self.apply_consequence). Isso diz ao Anvil para capturar o clique do botão que acabamos de criar na memória e enviá-lo direto para nossa função de consequências!

💻 ETAPA 7 — CÓDIGO PYTHON COMPLETO Código Corrigido - Separação do Evento de Reset
📄 form1.py 
from anvil import *

class Form1(Form1Template):
  
  def __init__(self, **properties):
    self.init_components(**properties)
    
    # === BASE DE DADOS DO JOGO (O MAPA DA HISTÓRIA) ===
    self.historia_db = {
      "entrada": {
        "texto": "Você está na entrada de uma caverna fria. Ouça água e rosnados.",
        "opcoes": [
          {"texto": "Explorar túnel úmido", "prox_fase": "tunel", "vida": 0, "energia": -2, "chave": True},
          {"texto": "Ir para o salão escuro", "prox_fase": "salao", "vida": -3, "energia": -1, "chave": False}
        ]
      },
      "tunel": {
        "texto": "Você escorregou! Mas achou uma Chave Dourada na lama. É um beco sem saída.",
        "opcoes": [
          {"texto": "Voltar para a entrada", "prox_fase": "entrada", "vida": 0, "energia": -1, "chave": False}
        ]
      },
      "salao": {
        "texto": "Um Goblin lhe atacou no escuro! Você corre para a grande Porta Final.",
        "opcoes": [
          {"texto": "Tentar abrir a fechadura", "prox_fase": "verificar_porta", "vida": 0, "energia": -1, "chave": False}
        ]
      }
    }
    
    # Inicia a primeira partida automaticamente quando o App abre
    self.reset_game()

  # ==========================================
  # EVENTOS DA INTERFACE (Aba Design do Anvil)
  # ==========================================
  
  # Evento gerado ao clicar no botão btn_reiniciar
  def btn_reiniciar_click(self, **event_args):
    # Apenas chama a lógica de reset isolada abaixo
    self.reset_game()


  # ==========================================
  # LÓGICA DO JOGO (Funções Internas)
  # ==========================================

  # 1. FUNÇÃO DE REINÍCIO
  def reset_game(self):
    # Dicionário de Estado do Jogo atual (game_state)
    self.game_state = {
      "stage": "entrada",
      "life": 10,
      "energy": 8,
      "has_key": False
    }
    self.painel_botoes.visible = True
    self.atualizar_tudo()

  # 2. FUNÇÃO CONTROLADORA GERAL
  def atualizar_tudo(self):
    self.update_ui()
    self.update_story()
    self.render_actions()

  # 3. ATUALIZAR STATUS (VISUAL)
  def update_ui(self):
    self.lbl_vida.text = f"❤️ Vida: {self.game_state['life']}"
    self.lbl_energia.text = f"⚡ Energia: {self.game_state['energy']}"
    
    texto_chave = "Sim" if self.game_state['has_key'] else "Não"
    self.lbl_chave.text = f"🗝️ Chave: {texto_chave}"

  # 4. ATUALIZAR NARRATIVA
  def update_story(self):
    fase_atual = self.game_state['stage']
    
    # Pega o texto da fase no Banco de Dados da História
    if fase_atual in self.historia_db:
      self.lbl_historia.text = self.historia_db[fase_atual]["texto"]

  # 5. GERAR BOTÕES DINAMICAMENTE
  def render_actions(self):
    # Limpa botões da tela anterior
    self.painel_botoes.clear()
    
    fase_atual = self.game_state['stage']
    
    if fase_atual in self.historia_db:
      opcoes_da_fase = self.historia_db[fase_atual]["opcoes"]
      
      # Loop para criar um botão para cada opção disponível
      for opcao in opcoes_da_fase:
        # Cria o botão via código Python
        novo_botao = Button(text="> " + opcao["texto"], role="primary-color")
        
        # Salva a "consequência" dentro do próprio botão para usar depois (Truque de mestre!)
        novo_botao.tag = opcao
        
        # Conecta o clique do botão à função apply_consequence
        novo_botao.set_event_handler('click', self.apply_consequence)
        
        # Adiciona o botão no painel visual da tela
        self.painel_botoes.add_component(novo_botao)

  # 6. APLICAR REGRAS APÓS O CLIQUE
  def apply_consequence(self, sender, **event_args):
    # 'sender' é o botão exato que o usuário clicou.
    # Recuperamos a opção que salvamos na 'tag' dele.
    escolha = sender.tag
    
    # Aplica matemáticas do Estado do Jogo
    self.game_state['life'] += escolha['vida']
    self.game_state['energy'] += escolha['energia']
    
    if escolha['chave']:
      self.game_state['has_key'] = True
      
    nova_fase = escolha['prox_fase']
    
    # --- VERIFICAÇÕES DE FIM DE JOGO ---
    
    # Lógica Especial da Porta Final
    if nova_fase == "verificar_porta":
      if self.game_state['has_key']:
        self.lbl_historia.text = "✨ VITÓRIA! Você abriu a porta e fugiu com o tesouro! ✨"
      else:
        self.lbl_historia.text = "🔒 GAME OVER. A porta está trancada e os Goblins te alcançaram..."
      self.painel_botoes.visible = False  # Esconde as ações
      self.update_ui()
      return # Encerra a função
      
    # Lógica de Morte por Status Zero
    if self.game_state['life'] <= 0 or self.game_state['energy'] <= 0:
      self.game_state['life'] = max(0, self.game_state['life'])
      self.lbl_historia.text = "💀 GAME OVER. Você desmaiou por exaustão ou ferimentos."
      self.painel_botoes.visible = False
      self.update_ui()
      return

    # Se não morreu, atualiza o status para a nova fase e recomeça o ciclo!
    self.game_state['stage'] = nova_fase
    self.atualizar_tudo()
📖 ETAPA 8 — EXPLICAÇÃO DETALHADA DO CÓDIGO Os Segredos do Data-Driven Design

🔌 Separando o Evento da Lógica

O evento btn_reiniciar_click apenas chama a função interna reset_game(). Fazemos isso para poder chamar o reset_game() lá no topo da tela também (no __init__), sem precisar clicar em nada para o jogo começar. Isso se chama Reutilização de Código!

📁 Dicionário `game_state`

No lugar de criar 4 variáveis soltas, agrupamos Vida, Energia, Chave e Fase num único dicionário. Isso mantém o "coração do jogo" organizado e fácil de debugar.

🗺️ O Mapa (historia_db)

A maior sacada aqui: separar a história do código. Temos um dicionário com todas as fases. Para adicionar novas salas, basta escrever no historia_db sem mexer em NENHUM botão!

🧱 `.add_component()`

O LinearPanel começa vazio. Na função render_actions(), usamos .add_component(novo_botao) para desenhar botões na tela em tempo real baseados no banco de dados.

🏷️ A Propriedade `.tag`

No Anvil, todo componente tem uma propriedade invisível chamada .tag (A Etiqueta). Nós guardamos o Dicionário inteiro da consequência do botão lá dentro, para recuperá-lo na hora do clique.

📨 O Argumento `sender`

A função apply_consequence(self, sender, ...) recebe o sender (o remetente). Graças a isso, lemos sender.tag e sabemos exatamente de qual botão veio a ação, sem precisar criar um evento para cada botão do jogo.
